# خياطتي — الدفعة 4 (المراحل 1–8)

## بناء APK عبر GitHub Actions

المشروع المرفق يحتوي على كود Flutter فقط، ولا يحتوي على مجلد Android أو ملفات Gradle أو ملف Drift المولّد. لذلك يقوم ملف GitHub Actions تلقائياً بإنشاء منصة Android، ثم تنزيل الحزم، وتوليد كود قاعدة البيانات، وتشغيل الفحص والاختبارات، وأخيراً بناء APK.

1. ارفع محتويات هذا المجلد إلى مستودع GitHub.
2. افتح تبويب **Actions**.
3. اختر **Build Flutter APK** ثم **Run workflow**.
4. انتظر انتهاء جميع المراحل بنجاح.
5. افتح نتيجة التشغيل ونزّل artifact باسم `khayyati-release-apk`.
6. فك ضغط الملف وستجد `app-release.apk` لتثبيته على هاتف Android.

## البناء محلياً

```bash
flutter create --platforms=android --org com.khayyati --project-name khayyati .
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
flutter build apk --release
```

## خط Cairo (اختياري)

ضع `Cairo-Regular.ttf` و`Cairo-Bold.ttf` في `assets/fonts/` ثم فعّل تعريف الخط في `pubspec.yaml`.

## ما تم حتى الآن
**الدفعة 1:** الهيكل، قاعدة SQLite، المصادقة، العاملون، إعدادات المحل، سجل العمليات.

**الدفعة 2:** الزبائن، المقاسات، الطلبات والمراحل وسجلها، صورة الموديل، لوحة رئيسية أولية.

**الدفعة 3 (جديد) — قاعدة البيانات صارت الإصدار 2 (ترحيل تلقائي):**
- من نموذج محل العبايات الورقي: مقاسات العبايات التسعة (الطول، العرض، الخصر، الورك، الكتف، يد الإبط، وسع اليد، فتحة اليد، كلوش)، لوحة **رسم باليد** داخل الطلب، مسميات «الواصل» و«تابع التفصيل»، واسم المحل الافتراضي «مركز ملكة الجمال للعبايات الراقية».
- **الدفعات:** دفعات متعددة لكل طلب، منع تجاوز السعر (إعداد يسمح به من الإعدادات)، إبطال دفعة بسبب للمدير فقط (لا حذف)، سجل تحصيل.
- **الديون وكشف الحساب:** ديون الزبائن حسب المحل والزبون، كشف حساب برصيد جارٍ.
- **المصروفات:** 8 فئات، بحث، تعديل وإلغاء موثّق للمدير.
- **المخزون:** مواد، شراء بمتوسط تكلفة مرجّح، استلام/خصم/هالك، نقل بين المحلين، تنبيه النقص، سجل حركة.
- **ربط القماش بالطلب:** خصم مرة واحدة، منع التكرار، استرجاع موثّق، إرجاع تلقائي اختياري عند الإلغاء. + أجور العاملين وتكاليف مباشرة.
- **الموردون:** مشتريات نقدية وآجلة، مستحقات، دفعات، كشف حساب.
- **الحسابات والأرباح:** الإيراد يُعترف به عند التسليم، العربون ليس ربحاً، لا ازدواج في التكلفة، حسب المحل أو الإجمالي وحسب الفترة.
- الصلاحيات تُفرض في الطبقة البرمجية (وليس الواجهة فقط).
- قسم «المزيد» في الشريط السفلي يضم الأقسام الجديدة.

**الدفعة 4 (جديد) — الفواتير والتنبيهات:**
- **الفاتورة (PDF بالعربية):** شعار المحل واسمه وهاتفه وعنوانه، رقم الفاتورة (مشتق من رقم الطلب: `INV-...`)، بيانات الزبون والطلب، السعر والمدفوع والمتبقي، الدفعات، الملاحظات، عبارة الشكر. تصميم مستقل لكل محل (A4 أو ورق حراري بعرض قابل للضبط).
- **ورقة الطلب:** بتصميم نموذج محل العبايات الورقي (المقاسات التسعة، بيانات العميل، نوع القماش، تابع التفصيل، الرسم) للطباعة في الورشة.
- **المعاينة والطباعة والمشاركة** من زر الطابعة في شاشة الطلب. الطباعة عبر خدمة الطباعة في Android (USB / Wi-Fi / Bluetooth حسب ما تدعمه الطابعة أو تطبيقها المرافق). الطابعات الحرارية التي تطلب أوامر ESC/POS مباشرة عبر البلوتوث غير مدعومة بعد.
- **الإعدادات:** إعدادات الفاتورة لكل محل (الورق، العملة، عبارة الشكر، الملاحظات) وشعار المحل من «بيانات المحل».
- **التنبيهات المحلية (بدون إنترنت):** تسليم اليوم، تذكير قبل التسليم، الطلبات المتأخرة، نقص المخزون، ملخص الديون الأسبوعي. تُجدول لـ14 يوماً وتُحدَّث تلقائياً. شاشة إعدادات التنبيهات من «الإعدادات».
- **خطوط PDF:** يستخدم DejaVu Sans المضمّن في `assets/fonts/pdf` (يدعم العربية ويعمل بدون إنترنت). لخط أجمل ضع Cairo هناك وغيّر الاسم في `invoice_service.dart`.
- خطوة جديدة في الـ workflow: `tool/patch_android.py` تضيف صلاحيات الإشعارات وتفعّل desugaring تلقائياً بعد `flutter create`.

## المتبقي
التقارير (PDF/Excel) ← النسخ الاحتياطي والاستعادة ← إعدادات متقدمة (تخصيص الحالات، المخزون) ← الاختبارات النهائية وAPK.
